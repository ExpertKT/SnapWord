0 · 这一版的三条决定

  1. 层次靠描边，不靠底色差。实测 elevated #101111 对 surface #0d0d0d 的对比度只有 1.03:1，肉眼几乎分不出来。所以面板/输入框/菜单的边界必须靠 hairline 描边来切， 色阶只用来表达"谁在上面"（悬停→card，选中→card+强描边）。
  2. 控件站到同一条 32px 线上。参考系统给的是 36px 高 + 8/16 padding（那是它自己的 button-md）；SnapWord 是浮层小工具，32px 更贴它的体量。这一版把下拉框补到 32px， 现在卡片和面板里所有控件实测同为 32px。
  3. 所有颜色、圆角、时长都只能从令牌表取。本轮把 QSS 里写死的 6 处颜色收进了令牌表 （见 §3），并在文档里留了"QSS 不能写 # 注释"的坑——那条坑能把后面所有规则一次性吃掉。
  4. （第三轮新增）识别符号＝一道光边。"没特色"的解法不是加装饰，而是把一个符号重复出现在三个表面上： 细边悬停时亮起的 2px 竖直蓝条（带 180ms 生长动画）、面板头下 1px 的水平渐隐蓝线（#streak）、 卡片顶沿那道 hairline-strong 受光边。渐变色标只准用令牌，透明不算颜色。
  5. （第三轮新增）两个 Qt 的坑当场改写了规范：圆角超过控件半高不会钳成半圆而是静默变直角 （整圆胶囊改为按半高取值：#chip 8px / #pill 12px）； QSS 不支持 #a, #b {} 逗号分组选择器（共用样式只能各写各的）。都写进了 docs/UI-STYLE.md。

S› SnapWord
  • 原来的丑有明确病根：字标是 "S\nn\na\np\nW\no\nr\nd" 一个字母一行， 行距把字距拉散，顶部再孤零零一个 16px 的字母——远看就是一列碎方块。
  • 现在整条自绘（QPainter，class Rail）：顶部 18×18 monogram 方块 （blue-soft 底 + blue 的 S，圆角 6）；中间把 "SnapWord" 整词旋转 90° 成竖排（字距 0.8px 连续）； 底部箭头随展开/收起翻向。不再有子控件，鼠标事件不会被子控件吃掉 （原实现靠 WA_TransparentForMouseEvents 补救的问题随之消失）。
  • 悬停光边：左内缘一道 2px × 40px 的蓝条，高度用动画从 0 长出来（180ms OutCubic 进、120ms InCubic 出）。 动画走 barH 这个 Qt 属性（QtCore.Property），照旧经 _anim() 留引用，只动属性不动布局。
  • 抽屉手感：展开动画缓动 OutCubic → OutQuint，尾段收得更狠，面板"抽出来"才到位；收起仍走 InCubic。
  • 面板头下加了 #streak：1px 水平蓝线从左往右渐隐——细边、面板、卡片共用同一道"光边"识别符号 （卡片的版本是顶沿 hairline-strong 受光边 + card → surface 竖向渐变底）。
  • 面板和细边仍是两块各自控件、靠绝对坐标拼成一整条，不是 layout——layout 在窗口变窄时会把细边留在旧坐标跑到窗口外。 左右角规则也不变：左侧两角 10px 圆、右侧两角方（贴屏幕边不能有圆角缺口），现在由绘制路径直接保证。

5 · 动效：什么能动、什么不能动

场景时长缓动动什么
面板展开/收起180msOutCubic窗口 geometry 宽 26↔352，面板 x 同步滑
卡片弹出180msOutCubicwindowOpacity 0→1 + pos 从 +10px 上来
卡片长高160msOutCubicgeometry 高度，锚左上
卡片关闭120msInCubic淡出，动画结束才 hide()
设置对话框进/出（本轮补）120msIn/OutwindowOpacity；出场统一走 Settings.done()，动画结束才真的关闭
托盘菜单进场（本轮补）120msOutCubic菜单 windowOpacity 0→1；只做进不做出
  • 禁区：只动 geometry / pos / windowOpacity；不动 min/max 尺寸（会重算 QSS 抖动）； 所有动画对象走 _anim() 留引用；浮层窗口的 WA_ShowWithoutActivating 全程保持，动画期间不抢焦点。
  • 合并连发：长高有 _resizing 闸门 + 高差<20px 跳过；关闭有 _closing 闸门。
  • QMenu 为什么只做进：菜单收起由 Qt 内部即时处理，拿不到稳定的"关闭前"时刻，硬做淡出会先隐藏再动画＝闪。

9.1 onboarding 补课：DeepSeek 怎么接（2026-09-29）

设置窗里"DeepSeek 地址 / 模型 / Key"三行之前只有一行泛泛的脚注，用户拿到不知道：Key 去哪申请、 填完算不算成功。现在 Key 框正下方挂一块 #tip 引导条，三段式——

  • 先解除焦虑：第一行就说"不接也能用：问答默认走本地 9B（免费、不花 token）"，DeepSeek 是可选增强；
  • 可执行的三步：① platform.deepseek.com 注册后在 API Keys 创建 → ② 复制 sk- 开头的 Key → ③ 粘进 Key 框保存；配一个「打开申请页」直达按钮（QDesktopServices.openUrl）；
  • 确定答案：「测一下能不能通」——后台线程发一个只花 1 个 token 的请求（providers.deepseek_up，12 秒短超时），401/402/422 翻译成人话（"Key 不对或已失效"/"余额不足"/"检查模型名"），状态字绿=green、红=red，只在真有结论时才上语义色。

状态机：没 Key → 显示三步 + 状态"还没接"；填了 Key → 三步收起、出现「测一下」；测完 → 绿/红结论。 表单加长后装进滚动区并夹在屏高 90%（Settings.showEvent 首显按内容量一次尺寸）。
